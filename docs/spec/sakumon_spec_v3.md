## 0. 改修の背景（判断の理由）

- 旧 `talk`（対話）は、到達構造・目標・直前の成立問題を受け取っておらず、「数量関係を渡さない」「1つ分／いくつ分／何倍を使わない」という一律の禁止のもとで「求めるものを変えてみよう」を言い換え続けるしかなかった。9/15 のログでは、児童の「求めているものって何？」という具体的な質問に答えられず、同じ言い換えが10回以上続く例が複数の児童で見られた。
- うまくいった数少ない例（33番・41番）は、いずれも**除数（8）が場面の中で何を指すか**に触れたときだった。本改修はこの観点を軸に据え直す。
- 旧仕様の「中」（役割指定のみ）は 9/15 のログで新構造到達 0件だったため、「中」と「強」を統合し、役割指定＋題材固定を1段にした。

## 1. 全体像

Phase2（支援あり）でのみ動く。支援は **4段階** に統合する。

| 強度 | 名称 | 内容 |
|---|---|---|
| 0 | 促し | 称賛のみ（新構造／同構造1回目） |
| 1 | 弱 | **役割の宣言（2ターン）**：直前の問題で除数が何をあらわすかを児童に言わせ（必要なら1回だけ訂正）、次の作問で除数を何の数にするかを予告させる |
| 2 | 中 | **役割指定＋題材固定**：除数を何の数にしてほしいかをシステムが直接指定し、題材はそのままでよいと伝える |
| 3 | 強 | **場面文提示**：求める文の手前までの場面文を渡し、問いだけを児童に書かせる |

対話（`talk`）は、現在の強度・目標・到達構造・直前の成立問題を参照し、**「現在の強度が許す情報だけを話してよい」**という境界で LLM が声かけを作る。

児童向け語彙は「求める」に統一。構造名（等分除・包含除・倍）は児童に一切出さない（v2 6章）。

## 2. 状態機械

### 2-1. 保持する状態（`sessions`。フェーズスコープ）

| 変数 | 型 | 意味 |
|---|---|---|
| `produced` | set | 到達した構造の集合（`chat_logs` から `user_id + phase` で引く） |
| `declared` / `declared_by` | str \| None / `"child"` \| `"system"` \| None | 現在の目標（予告） |
| `stuck_count` | int | 新しい構造に到達しなかった**成立**作問の**連続**回数 |
| `miss_count` | int | 予告（宣言）と産出の不一致の累積回数 |
| `help_count` | int | **新設**。`talk` が「支援要求」に分類された回数 |
| `strength` | int | **新設**。現在の強度 0〜3。**状態として保持し、カウンタから毎回計算し直さない** |

### 2-2. カウンタの規則

```
不成立の作問          → 何も動かない（形式の支援のみ）
成立・新構造          → produced に追加、stuck = miss = help = 0、strength = 0
成立・既出構造        → stuck += 1
予告あり・一致        → declaration_met = 1、miss = 0
予告あり・不一致      → declaration_met = 0、miss += 1
対話・支援要求        → help += 1（stuck / miss は動かない）
対話・それ以外        → 何も動かない
役割の答え・予告      → 何も動かない
再送（resend）        → 何も動かない
3つそろった後         → 何も動かない（支援なし）
```

### 2-3. 強度の遷移（`main.decide_strength`）

```
新構造到達                    → 0
強度 0 → 1                    → stuck が 2 に達したときだけ（miss / help だけでは上がらない）
強度 1 以上                   → stuck / miss / help のいずれかが増えたターンごとに +1（上限 3）
同じターンで stuck と miss が両方増えても +1 は 1 回（1回の失敗＝1段）
```

- `strength_trigger`（ログ）：そのターンで強度を上げた原因 `stuck` / `miss` / `help`。上がらなければ `none`（上限3で据え置きも `none`）。同時なら `miss > stuck > help` の優先で1つ。
- **設計判断**：この規則は Wood & Middleton の随伴的指導の原則（失敗で1段強め、成功で1段弱める）に基づく。**閾値の具体的な数値（0→1 は stuck=2、上限3）は先行研究から直接導かれたものではない**。「同じ構造を1回くり返しただけでは介入しない」は旧仕様から踏襲。
- 予告一致で miss を 0 に戻す規則は v2 から維持（強度は状態なのでこの 0 戻しは強度に影響しない。ログの値にだけ効く）。

### 2-4. 作問受信時のフロー

```
作問を受信 → ai_judge
  ├ 不成立 → form（issue に応じた1点）。強度・カウンタ据え置き。終了
  └ 成立（構造 S）
      ├ declared あり → S==declared なら met=1, miss=0 ／ 違えば met=0, miss+=1
      ├ S が新構造 → produced に追加、全カウンタ・強度 0 ／ 既出 → stuck+=1
      ├ produced が3つ → done。終了
      ├ strength を遷移させる
      │   0 → praise
      │   1 → prompt（弱・ターン1を開く。dialog="role"）
      │   2 → prompt（中。未到達構造を固定順 tobun→hougan→bai で declared=system に立てて文言）
      │   3 → prompt（強。同上＋場面文）
      └ declared は消費（中・強はその直後にシステムが新しい目標を立てる）
```

### 2-5. 対話受信時のフロー（フェーズE）

```
対話を受信（classify=taiwa、待っている対話ターンも無い）
  → talk：LLM に「いまの状況」（強度・目標・到達構造・成立作問の一覧と直前の問題）を渡して文言＋ is_help_request
  → is_help_request=true なら help+=1 → 強度を遷移
      強度が 2 以上になって目標が無ければ、未到達構造を declared=system で立てる
  → 文言は更新前の強度で生成済み。新しい強度・目標の反映は次ターンから
```

## 3. 各段階の文言と挙動

`{dividend}` `{divisor}` `{ref_no}`（直前の成立作問の表示番号）`{item}`（直前の成立作問の物の名前）`{unit}`（その助数詞）は実行時に埋める。`{item}` `{unit}` は `ai_judge` の判定出力（`item` / `unit`）から取る。

3-1（ラベル）・3-2（形式の支援）・3-3（強度0の称賛）・3-7（完了）は v2 のまま。
形式の支援の issue に `reversed`（比較の向きが逆）を追加したが、児童向け文言は暫定で `wrong_number` と同じ（`_FORM_ALIAS`）。

### 3-4. 弱（強度1）＝役割の宣言（2ターン）

**ターン1**（作問への応答として出す。`dialog="role"`）

> {ref_no}ばんの お話で、{divisor}は 何を あらわして いるかな？

児童の自由記述を `ai_classify.classify_role` で分類し、`role_answer` に**訂正前の生の値**として必ず保存する：
`people`（分ける相手の数・人数）／`per_one`（1人分の数）／`base`（比べる相手の量）／`dont_know`（わからない）／`unknown`（判別不能・LLM失敗）

判定結果から見た除数の実際の役割（`ai_dialogue.expected_divisor_role`）と突き合わせる：
`tobun` → `people`、`hougan` → `per_one`、`bai`（倍率・割合を求める）→ `base`、`bai`（基準量を求める。除数が倍率）→ 確定できない（None）

- 一致、または `dont_know` / `unknown`、または役割が確定できない → ターン2へ
- 不一致（役割が確定でき、答えが3役割のどれかに確定したときだけ）→ **1回だけ訂正**。正解の役割名は言わず、児童自身の問題文の除数の句を引用して問い返す（`role_corrected=1`、`dialog="role"` のまま）：

> 本当に そうかな？ お話では『{phrase}』と 書いて あるよ。
> {divisor}は 何の 数に なって いるかな？

  `{phrase}` は `extract_divisor_phrase`（LLM。元の文に含まれる30字以内の句だけ採用）→ 取れなければ除数を含む文（40字以内）→ それも無理なら引用なし：

> 本当に そうかな？ お話を もう一度 読んで みよう。
> {divisor}は 何の 数に なって いるかな？

- 訂正後の2回目の答えは記録するが、正誤にかかわらずターン2へ進む（ループさせない）

**ターン2**（`dialog="declaration"`）

> じゃあ 次は、{divisor}を 何の 数に して みたい？

児童の自由記述を `classify_declaration` で `tobun` / `hougan` / `bai` / `unknown` に分類し、`input_type="declaration"`、`declared_by="child"` で立てる。`unknown` なら立てない（再質問もしない）。目標が立てば画面上部に固定表示。

**共通**

- どちらのターンも作問と同じ入力欄から送る（入力欄は1つ。対話モードは緑枠・プレースホルダなし）
- どのターンでも作問を送ってきたら対話は打ち切って通常の作問処理（ブロックしない。予告は立たないまま）
- 待っているターンが無い状態で対話モードから届いた文は `talk`
- どのターンを待っているかは**サーバが直前のログ行から決める**（`main._pending_dialog`。再入場時の復元も同じ）
- 役割の答え・予告ではカウンタ・強度は動かない
- 弱では構造のラベル（1つ分の 大きさ／いくつ分／何倍）を出さない
- 旧 3-5 の3択（自己ラベル、`/api/self_label`）は廃止。`self_label*` 列は残すが書き込まない

### 3-5. 中（強度2）＝役割指定＋題材固定

`declared=指定構造`, `declared_by="system"`。3択はない。入力欄は作問モードのまま。

| 指定 | 文言 |
|---|---|
| `tobun` | {item}の お話は そのままで いいよ。{divisor}を「何人で 分けるか」の 数に して みよう。 |
| `hougan` | {item}の お話は そのままで いいよ。{divisor}を「1人分の 数」に して みよう。 |
| `bai` | {item}は そのままで いいよ。{divisor}を、もう 1人が もっている {item}の 数に して みよう。{dividend}{unit}と くらべると、どんな ことが 求められるかな？ |

`{item}` が取れないとき：文頭の「{item}の お話は／{item}は」を「{ref_no}ばんの お話は」に置き換え、文中の {item} は「もの」、{unit} は「こ」。

### 3-6. 強（強度3）＝場面文提示

`declared=指定構造`, `declared_by="system"`。

| 指定 | 文言 |
|---|---|
| `tobun` | 「{item}が {dividend}{unit} あります。{divisor}人で 同じ 数ずつ 分けます。」 この あとに、求める 文を 書いて みよう。 |
| `hougan` | 「{item}が {dividend}{unit} あります。1人に {divisor}{unit}ずつ 分けます。」 この あとに、求める 文を 書いて みよう。 |
| `bai` | 「{friend_name}さんは {item}を {dividend}{unit}、{friend_name_alt}は {divisor}{unit} もって います。」 この あとに、「何倍」を つかって 求める 文を 書いて みよう。 |

- `{friend_name}`：学級の実在児童と重複する固定名を避けるため、`FRIEND_NAMES = ("たろう", "はなこ")` からセッションIDの偶奇で周期的に選ぶ。`{friend_name_alt}` は「お友だち」で統一。名簿照合は行わない
- `{item}` `{unit}` が取れないときは「もの」「こ」

## 4. 対話（`talk`）の設計（フェーズD）

### 4-1. LLM に渡す情報（`ai_dialogue._llm_message(..., context)`）

- 到達構造（構造名の集合。旧は件数のみ）
- 現在の目標構造（あれば。児童の予告またはシステムの指定）
- 現在の強度（0〜3）
- 児童が作れた問題の一覧（番号・本文・その問題で除数が指していたもの）と、直前の成立問題（本文・除数の役割・物）
  除数の役割は `ai_judge` の `structure` / `unknown` から `divisor_role_label` で引く

### 4-2. 境界（強度依存）

| 強度 | 話してよいこと |
|---|---|
| 0・1 | 除数が何を指すかを児童に問い返してよい。**システムから答え（役割）を言わない**。「1つ分の 大きさ／いくつ分／何倍／1人分」の語を出さない。次の作問で除数を何にするかも指定しない |
| 2 | 除数をどうしてほしいかをシステムから直接言ってよい。上記の語を使ってよい。題材を固定してよい（「{item}の お話は そのままで いいよ」）。場面文は渡さない |
| 3 | 上記に加え、場面文（求める文の手前まで）を渡してよい。問いは書かない |

どの強度でも：
- 許可：児童がすでに作った複数の問題どうしの違い（または同じであること）を、除数の役割で説明する
- 禁止：答え（商の数値）、構造名（等分除・包含除・倍）、問いまで含む完成した問題文、穴うめの型
- 児童の誤った「同じ／ちがう」の主張を、共感のために安易に肯定しない。内容を確認せずに褒めない
- 休けい・終了の提案、謝りすぎ、語彙6章の禁止語（v2 から維持）

### 4-3. コード側ガード（`violates_boundary(message, "talk", expression, strength)`）

- 全強度：構造名、**商の数値**（「6こ」「6になる」等。「6ばん」「6つ」は許容）、語彙6章、休けい提案
- 強度0・1のみ：求める量の語（1つ分／いくつ分／何倍／1人分…）、被除数と除数の同時出現
- 文字数上限：0・1＝120、2＝140、3＝180
- 違反したら1回だけ再依頼、2回目も違反なら定型文（`TALK_FALLBACK` / `TALK_FALLBACK_REWRITE`）
- 役割の語（「人数」等）はガードで落とさない（「同じ／ちがう」への説明が全強度で許可のため）。強度0・1の直答はプロンプトで抑える

### 4-4. 支援要求の判定（フェーズE）

出力JSON `{check, message, state, is_help_request}` の `is_help_request` を、文言と同じ1回の呼び出しで判定させる。
- true：「ヒント」「わからない」「思いつかない」「どうすればいい」「答え教えて」など、作問を進めるための助けの要求（困りの表明も含む）
- false：雑談・感想（「あーなるほど」「やった」）、疑問への応答依頼（「これって足し算？」「8ってなんの数？」）
- LLM 不通で定型文に落ちたときは NULL（未判定）

## 5. ai_judge の出力（フェーズC・F）

```
valid:     true / false
structure: tobun / hougan / bai / invalid
unknown:   one_unit / num_units / ratio / base / rate / null
issue:     null / scene_contradiction / wrong_number / reversed / incomplete_text / wrong_operation / no_question / not_problem
item:      被除数が数えている物の名前（読み取れなければ null）
unit:      被除数に付く助数詞（読み取れなければ null）
```

- `reversed`（新設）：{dividend} と {divisor} の両方を使っているが比較の向きが逆で {divisor}÷{dividend} になる。使う数がちがう `wrong_number` と区別する
- `valid=false` なのに `issue` が無い／未知（または `valid=true` なのに `structure=invalid`）のときは、以前は一律 `not_problem` にしていたが、「〜があります」から書けている入力にもその文言が出るため、本文の形から寄せる（`_fallback_issue`：場面の文も数も無い → `not_problem`、問いの文が無い → `no_question`、それ以外 → `wrong_number`）

## 7. ログ（`chat_logs`）

v2 の列に加えて：

| 列 | 内容 |
|---|---|
| `item` / `unit` | 判定が読み取った物・助数詞 |
| `role_answer` / `role_corrected` | 弱ターン1の分類（訂正前の生値）／訂正を出したか |
| `is_help_request` | `talk` の支援要求判定（未判定は NULL） |
| `help_count` | このターン後の help |
| `strength` | このターン後の強度。`talk` 行では `prompt_strength`＝文言を生成した強度（更新前）と区別 |
| `strength_trigger` | このターンで強度を上げた原因（`stuck` / `miss` / `help` / `none`） |
| `target_structure` | このターンの AI の発話が指した目標構造 |

`input_type` に `role` が加わる（`self_label` は出なくなる）。フェーズ1・3では支援に関わる列は NULL。
