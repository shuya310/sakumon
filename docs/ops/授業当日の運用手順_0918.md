# 9月18日 授業実践：運用手順（教師・システム担当用）

## 0. 前日までに（Render／ローカル共通）

1. **環境変数 `ADMIN_PASSWORD` を必ず設定する。** 未設定だとサーバは起動しない。
   - Render：Dashboard → Environment に `ADMIN_PASSWORD=（任意の文字列）` を追加してから Deploy。
   - ローカル：`.env` に `ADMIN_PASSWORD=...`（`.env.example` 参照）。
2. デプロイ後、`https://sakumon.onrender.com/admin` を開き、ブラウザの認証ダイアログに
   **ユーザー名は何でもよい／パスワードに ADMIN_PASSWORD** を入れて入れることを確認。
3. 式は出席番号の奇偶×フェーズで自動的に決まる（奇数番 21÷3 → 24÷4 → 30÷5、偶数番 30÷5 → 24÷4 → 21÷3。フェーズ2 は 9/1 の紙と同じ 24÷4）。
   管理画面「フェーズ管理」の表で確認する。個別に変えたいときだけ「児童一覧・ログ」のセッションの「式を変更」。
4. リハーサルをした場合は、当日の朝までに **「児童一覧・ログ」でリハーサルに使った出席番号のセッションを削除する**。
   1児童1フェーズ1セッションなので、消さないとその出席番号の児童はリハーサルのセッションを再開してしまう。
   **本番の出席番号（01〜33 など）のデータが0件であることを確認してから始める。**
5. Render 無料枠はしばらくアクセスが無いとスリープするので、授業10分前に一度アクセスして起こしておく。

## 1. 授業の流れ（2コマ・85分）

| 時間 | 操作（教師） | 児童の画面 |
|---|---|---|
| 開始 | フェーズが **1** になっていることを確認 | 出席番号を入れて「次へ」。式が表示され、入力欄と送信ボタン（と入力欄の下に「作った お話を 見る」）。送ると「おくったよ」。右の「作った 問題」に送った作問が番号付きで並ぶ（判定は出ない） |
| 残り約2分 | 口頭で「作った お話を 見る から、ちがう種類のお話を3つ選んで送ってね」と伝え、管理画面の **「声がけした」** を押す（時刻の記録だけ。児童画面には何も出ない） | 「作った お話を 見る」→ 一覧から3つ（3問未満ならその数）にチェック →「これで 決定」→「はい」。「もどる」で作問を続けられ、何度でも選び直せる |
| 15分後 | 「フェーズ2」ボタン → 確認ダイアログ OK | 全端末に「ここまでで いったん おしまい」が約3秒出て、**新しい画面**で支援が始まる（フェーズ1の作文は残らない。入力中の文も消える） |
| 50分後 | 「フェーズ3」ボタン → OK | 「いったん おしまい」→ 別の式の新しい画面（履歴・信号機はリセット）。送ると「おくったよ」 |
| 残り約2分 | フェーズ1と同じく口頭で促し、「声がけした」を押す | フェーズ1と同じ選択画面 |
| 終了 | 「児童一覧・ログ」タブ → 「CSVダウンロード」 | ― |

- 切替は児童側の操作なしで、**最大5秒**で全端末に反映される（5秒ポーリング）。
- 誤って別のフェーズを押した場合は、正しいフェーズを押し直せばよい（フェーズごとに別セッション。押し直せばそのフェーズの画面に戻り、データは消えない）。
- 児童が誤ってログアウト／リロード／タブを閉じても、出席番号を入れ直せば **同じフェーズのセッションに戻る**（それまでのやりとりも残っている）。

## 2. 授業中に教師が見るもの（フェーズ管理タブの「児童の状態」）

- 5秒ごとに自動更新。
- **赤い行 ＝ 今のフェーズで提出0問**。手が止まっている児童なので机間指導で拾う（システムは無入力を検出しない）。
- 「接続」：直近15秒以内に通信があれば接続中。
- 「到達」：●●● は左から 1つ分（等分除）／いくつ分（包含除）／何倍（倍）。
- 「予告」：いま立っている予告（児童が書いたか、システムが指定したか）と、その構造。
- 「反復／不一致／支援要求」と「強度」：同じ構造の連続回数・予告と違う構造を作った回数・「ヒント」「わからない」等を送った回数（いずれも新構造で0に戻る）と、いまの支援の強さ（0〜3）。不一致は赤。
- 「直近の応答」：フェーズ2のみ。形式／称賛／予告支援（弱・中・強）／対話／3つ達成／判定エラー。
- 「作った お話を 見る」（左のカード）：フェーズ1・3それぞれの選択送信済み人数と声がけの時刻。声がけ後に人数が増えない児童は机間指導で促す。
- 「判定」（左のカード）：フェーズ1・3は児童に「おくったよ」を返した**あと**に判定するので、「成立」「到達」は数秒〜十数秒遅れて埋まる。
  「未判定」が減らない／「失敗」が出たときは、API が復旧してから **「未判定・失敗を再判定」** を押す（サーバ再起動後も同じ）。
- **授業前にリハーサル分を消す**：「フェーズ管理」→「退避して全部消す」。CSV が手元にダウンロードされ、サーバの DB が `data/sakumon.db.backup_<時刻>_<メモ>` に複製されてから、全児童のセッション・ログ・選択・声がけが消える（確認語「消す」を入力）。フェーズは残るので、消したあとフェーズ1に戻す。

## 3. 児童への事前説明（システム利用の前）

フェーズ1は「支援なし」の事前測定なので、**フェーズ1の前は操作だけ**を説明し、言葉の意味（「求めるもの」）は**フェーズ2に切り替えた直後**に説明する。

**フェーズ1の前（操作のみ。中身に触れない）**
- 問題は「お話＋聞く文（〜ですか）」を **1回の送信にまとめて** 書く。途中で切って送らない
- 入力欄は1つ。問題も、聞きたいこと・困ったことも、同じところに書いてよい
- 右の「作った 問題」に送ったものが並ぶ。同じ問題を送り直しても増えない
- 「もう一度 おくって みてね」と出たら、そのまま送り直す
- 残り2分で「作った お話を 見る」から3つ選ぶ（運用手順どおり「ちがう種類のお話」。基準は言わない）

**フェーズ2に切り替えた直後（30秒。語の定義だけ）**
- 「ここからは返事が来ます。返事の中に **『求める もの』** という言葉が出てきます。『求める もの』は、お話の最後で聞いていることです」
  — 例は今日の式と無関係な問題1つで示す（例：「りんごが 5こ、みかんが 3こ。あわせて 何こ？」→ 求めるものは「あわせて何こか」）。
  **何人／何こ／何倍のような3つの例は挙げない**（挙げると全員に中の支援を先に与えたことになる）
- 「返事の意味がわからなかったら『どういうこと？』と書いていい」
- 「返事が来る前に次を書かなくていい。返事を読んでから書く」
- 「求めるものが**ちがう**とはどういうことか」は支援そのものなので説明しない（システムの段階に任せる）

## 3'. 児童の画面で起こること（フェーズ2）

- フェーズ2は新しいチャット画面から始まる。支援（信号機・お話リスト・水準）は**フェーズ2で打った内容だけ**を根拠にする。
- 不成立の作問 → 形式の支援（問いがない／数がちがう／お話になっていない／答えが書いてある、のうち1点だけ）。
- 成立した作問 → 称賛。児童が書いた問いの文を引用する：「新しい 問題が できたね！ この お話は、『何人に くばれますか』を 求める お話だね。今度は、**求める ものが ちがう** お話は 作れるかな？」
- 「求めるものって何？」「求めるものがちがうってどういうこと？」と聞かれたら（強度0・1）、児童自身の問いの文を指す定型：
  「1ばんの お話の 最後の 文、『何人に くばれますか』の ところが『求める もの』だよ。今度は、ここが ちがう お話を 作って みよう。」（何を求めればよいかは言わない。支援要求にも数えない）
- 同じ構造を2回くり返す（または「ヒント」「わからない」、作問のあと対話だけが3回続く）と**弱＝現在地の対比＋宣言（1ターン）**。何が同じかを児童の言葉2つ（4の使い方＋求めるもの）で言う：
  「2ばんの『4こずつ 買います』も 3ばんの『4つ くばると』も、4の 使い方は 同じで、どちらも **何人か**を 求める お話だね。じゃあ 次は、何を 求める お話に する？」
  （等分除・包含除を両方作っていれば「1ばんは 何人か、2ばんは 何こかを 求めたね。どちらも 24こを 分ける お話だね。じゃあ 次は、24こを 分けない お話に するなら、何を 求める？」）
  → 児童が同じ入力欄（緑枠）に短く答える（宣言）。「何こか」「1人分」「何倍か」「4人で分ける」のように答えれば「じゃあ、その お話を 作って みよう。」と返り、児童の言葉が式の下に「つぎは「何こか」」と固定表示される（誤字・誤答もそのまま。訂正しない）。
  「わかりません」には「わからなくても だいじょうぶ。じゃあ、求める ものが ちがう お話を 作って みよう。」、「クラスの話」のような言葉は「『クラスの話』だね。じゃあ、その お話を 作って みよう。」と返して作問に戻す（聞き直さない）。
  途中で問題を書けばそのまま作問として受け付ける（対話は打ち切り）。
- 弱のあとにさらに同じ構造をくり返す、宣言と違う構造を作る、または「ヒント」「わからない」のような支援要求を送る → 1段ずつ強くなる（上限は強）。
  ただし「ヒント」「わからない」で上がった直後は、児童が一度作問（不成立でも可）か宣言をするまで、もう一度「わからない」と言っても上がらない（連続で強まで飛ばない）。
  - **中**：「何人に 分けられるかを 求める お話に して みよう。4を、1人が もらう 数に するよ。えんぴつの お話は そのままで いいよ。」（目標＋手段＋題材はそのまま。システムが次の目標を指定。式の下に「つぎは「何人に 分けられるかを 求める お話」」。児童は宣言しない。
    等分除なら「1人分が 何本かを 求める お話に して みよう。4を、分ける 人の 数に するよ。…」、倍なら「24本は 4本の 何倍かを 求める お話に して みよう。4を、くらべる 相手の 数に するよ。…」）
  - **強**：「「えんぴつが 24本 あります。1人に 4本ずつ 分けます。」つづきの、求める 文を 書いて みよう。」（場面文を渡し、求める文だけ書かせる。倍は「たろうさんは えんぴつを 24本、お友だちは 4本 もって います。」つづきの、何倍かを 求める 文を 書いて みよう。）
  - 「ヒント」「わからない」で中・強に上がったターンは、対話の返事は出さず「そっか。じゃあ、こうして みよう。」に続けて中・強の文言が出る。
- 作問以外の入力（質問・つぶやき）への返事は、いまの強さに応じて内容が変わる（なし：自分の問題文の問いの文に目を向けさせるだけ／弱：「2ばんも 3ばんも、4の 使い方は 同じで、どちらも 何人かを 求める お話だね」と現在地を示して問い返す／中から：「1人分が 何こかを 求める お話に して みよう。4を、分ける 人の 数に するよ」と目標と手段を直接言う）。答え・構造名・次の問題の問いの文は言わない。
- 新しい構造ができれば回数・強さは0に戻り、称賛だけになる。3つそろうと「3つ とも できたね！ 1ばんは『何人か』、3ばんは『何こか』、4ばんは『何倍か』。同じ 24÷4 なのに、求める ものが ぜんぶ ちがう お話に なったね。時間まで、もっと 作って みよう。求める ものが 同じでも、ちがう お話なら いいよ。」
  以降の成立作問は「◯ばんも できたね。この お話は『…』を 求める お話だね。」だけで、支援は出ない。**早く終わった児童には教師から口頭で**「3つの お話で、4は それぞれ 何の 数だったか ノートに 書く」などを指示する。
- 右側の「作った お話 ● ● ○」は到達した数だけ（どれかは示さない）。フェーズ2のあいだ常に出る。「作った 問題」の一覧はフェーズ2では成立した作問だけ（弱・強の「◯ばんの お話」はこの番号）。
- 構造名（等分除など）は児童には一切見せない。図は出ない。

## 4. 分析用データ

- CSV の主な列：`phase`（1/2/3）、`input_type`（sakumon / taiwa / resend。弱の宣言は declaration）、`divisor_phrase`（成立作問の 4 の句）、`question_phrase`（成立作問の問いの文）、
  `valid`、`structure`、`unknown`（one_unit / num_units / ratio / base / rate）、`issue`（reversed＝比較の向きが逆 を含む）、`is_new`（フェーズスコープ）、
  `item` / `unit`（判定が読み取った物と助数詞）、
  `response_type`（form / praise / prompt / talk / done / error）、`prompt_strength`（文言を出した強度 0〜3）、
  `produced_structures`（その時点までの到達構造 "tobun,hougan"）、`stuck_count` / `miss_count` / `help_count`、
  `strength`（そのターン後の強度）/ `strength_trigger`（上げた原因 stuck / miss / help / talk / none）/ `target_structure`（発話が指した目標）、
  `declared_structure` / `declared_by` / `declaration_met`（宣言の行は `message` が児童の言葉。空なら unknown）、
  `is_help_request`（taiwa が支援要求か）、`latency_ms`（児童への応答時間）、`judge_status`（作問行の判定状態 pending / done / failed）/ `judged_at`（判定完了時刻）。`self_label*` / `role_answer` / `role_corrected` 列は残っているが使われない（旧 v3）。
- フェーズ1・3の選択：`selected`（最終選択に含まれる作問行＝1）、`selection_first_open_at`（選択画面を初めて開いた時刻）、`selection_last_at` / `selection_last_log_ids`（最終選択）、`teacher_call_first_at`（そのフェーズの最初の声がけ）。全履歴は DB の `selection_events`（open / submit）と `teacher_calls`。
- 時刻（`created_at` / `session_start` / `session_end`）は JST。`session_end` はログアウトかフェーズ切替の時刻（入り直すと消える）。
- フェーズ切替の時刻は DB の `phase_changes` テーブルにも残る。

## 5. トラブル時

- 児童の画面に「もう一度 ログインしてね」→ 出席番号を入れ直す。
- 判定が返らない → API側の一時的な失敗。児童には「うまく よみとれなかったよ。もう一度 おくって みてね。」と出る（ログは `issue=error`）。送り直せば判定し直す。
  フェーズ1・3では児童には何も出ない（「おくったよ」のまま）。ログは `judge_status=failed` になるので、あとで「未判定・失敗を再判定」。
- 管理画面に入れない → `ADMIN_PASSWORD` を確認。ブラウザを閉じて開き直すと認証ダイアログが再表示される。
