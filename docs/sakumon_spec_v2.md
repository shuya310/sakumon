## 1. 実装する機能の全体像

Phase2（支援あり）に「予告 → 産出 → 照合」のサイクルを入れる。

```
作問が成立するたびに：
  新しい構造なら         → 称賛（なし）
  同じ構造のくり返しなら → 回数に応じて 弱 → 中 → 強 と支援を強める
  予告を立てたのに
  違う構造を作ったら     → 一気に 中 へ、2回目からは 強 へ
```

- **弱**：次に何を求める問題にするか、自由記述で宣言させる
- **中**：自分の作った問題が何を求めているかを答えさせ（自己ラベル）、その後システムが次の目標を1つ指定する
- **強**：目標の指定に加えて、場面を固定する（「◯ばんの お話は そのままで いいよ」）

児童向け語彙は「求める」に統一。構造名（等分除・包含除・倍）は児童に一切出さない。

## 2. 状態機械

### 2-1. 動作範囲

**Phase2 でのみ動作する。** Phase1 / Phase3 では一切表示しない（記録のみ、現状維持）。

### 2-2. 保持する状態（フェーズスコープ。フェーズ開始時にリセット）

| 変数 | 型 | 意味 |
|---|---|---|
| `produced` | set | 到達した構造の集合（`ai_judge` 判定に基づく） |
| `declared` | str \| None | 現在の予告（構造の内部名） |
| `declared_by` | `"child"` \| `"system"` \| None | 予告を誰が決めたか |
| `stuck` | int | **新しい構造に到達しなかった成立作問の連続回数** |
| `miss` | int | **予告があったのに一致しなかった累積回数** |

### 2-3. カウンタの規則（最重要。ここを間違えると全体が壊れる）

```
不成立の作問        → stuck / miss は変化しない（形式の支援のみ）
成立・新構造        → produced に追加、stuck = 0、miss = 0
成立・既出構造      → stuck += 1
予告あり・一致      → declaration_met = 1、miss = 0
予告あり・不一致    → declaration_met = 0、miss += 1
対話（taiwa）       → 変化しない
再送（resend）      → 変化しない
```

- 不成立を数えない理由：形式のつまずき（問いが書けない等）と構造のつまずきは別物。混ぜると形式で詰まっている児童に構造の支援が飛ぶ。
- 「連続」であって累計ではない。**新構造に到達したら必ず両方 0 に戻す。** リセットが抜けると、一度詰まった児童が最後まで「強」に張り付く。
- `miss` は困り表明ではない。「いくつ分を求める」と宣言して等分除を作ったときにだけ立つ。

### 2-4. 強度の決定

```python
def decide_strength(stuck: int, miss: int) -> int:
    from_stuck = 0 if stuck <= 1 else (1 if stuck == 2 else (2 if stuck == 3 else 3))
    from_miss  = 0 if miss == 0 else (2 if miss == 1 else 3)
    return max(from_stuck, from_miss)
```

| 状況 | 強度 |
|---|---|
| 新構造（stuck=0）／同構造1回目（stuck=1） | 0：なし |
| 同構造2回目（stuck=2） | 1：弱 |
| 同構造3回目（stuck=3）または予告不一致1回目（miss=1） | 2：中 |
| 同構造4回目以上（stuck≥4）または予告不一致2回目以上（miss≥2） | 3：強 |

設計意図：同じ構造を1回くり返しただけでは介入しない（くり返し自体は児童にとって自然な行動）。介入が強まるのは、予告を立てたのに届かなかったときである。

### 2-5. 作問受信時の全体フロー

```
作問を受信 → ai_judge 実行
  ├ 不成立 → response_type="form"、issue に応じた形式の支援を1点だけ。終了
  └ 成立（構造 S）
      ├ declared あり → S==declared なら met=1, miss=0 ／ 違えば met=0, miss+=1
      ├ S が新構造 → produced に追加、stuck=0、miss=0
      │  既出構造 → stuck+=1
      ├ produced が3つ → response_type="done"、完了表示。終了
      ├ 強度を決定 → 対応する応答を表示
      └ declared をクリア
```

## 3. 各段階の文言と挙動

`{expr}`, `{dividend}`, `{divisor}`, `{target_label}`, `{ref_no}` は実行時に埋める。

### 3-1. 構造の児童向けラベル（内部名は児童に出さない）

| 内部名 | 児童向けラベル |
|---|---|
| `tobun` | 1つ分の 大きさ |
| `hougan` | いくつ分 |
| `bai` | 何倍 |

### 3-2. 形式の支援（`response_type="form"`）

issue に応じて**1点だけ**指摘。複数あっても最も重い1つに絞る。

| issue | 文言 |
|---|---|
| `no_question` | 求める ことを きく 文が ないみたいだよ。さいごに「〜は いくつですか」を 書いて みよう。 |
| `wrong_number` | {dividend}と {divisor}を つかう 問題に しよう。いまの お話だと しきが ちがって しまうよ。 |
| `not_problem` | まだ お話に なって いないみたいだよ。「〜が あります」から はじめて みよう。 |
| `scene_contradiction` | 求める ことの 答えが、お話の 中に もう 書いて あるよ。どこか さがして みよう。 |
| `error` | うまく よみとれなかったよ。もう一度 おくって みてね。 |

### 3-3. なし（強度0、`response_type="praise"`）

新構造に到達：

> 新しい 問題が できたね！
> ほかにも、**求めるものが ちがう** 問題は 作れるかな？

同じ構造を1回くり返し（確定文言）：

> いいね、また 一つ できたね。
> 今度は **求めるものが ちがう** 問題も 作れそうかな？

予告入力欄は出さない。

### 3-4. 弱（強度1、`response_type="prompt"`）

> つぎは **何を 求める** 問題に する？
> きめてから、作って みよう。

1. 自由記述の予告入力欄を表示（選択肢は出さない。プレースホルダも置かない）
2. 送信された文を LLM で `tobun` / `hougan` / `bai` / `unknown` に分類（`input_type="declaration"` で記録）
3. `unknown` → `declared` を設定しない。再質問もしない。作問入力欄に戻す
4. 分類できた → `declared=結果`, `declared_by="child"`、目標を画面上部に固定表示
5. 作問入力欄に戻る

分類プロンプトの基準：

- `tobun`：1つ分の大きさ・1人分・1皿分などを求めると書いている
- `hougan`：いくつ分・何人に配れるか・まとまりの数を求めると書いている
- `bai`：何倍か・もとにする量との比較を求めると書いている
- `unknown`：題材のみ（「りんごの問題」）・無関係・判断不能

### 3-5. 中（強度2、`response_type="prompt"`）— 2ステップ対話

**ステップ1（自己ラベル・自由記述）**

> いま 作って くれた 問題は、**何を 求めて いる** のかな？

原文を `self_label_text` に保存（`input_type="self_label"`）。

**ステップ2（選択肢で確認）**

> それは この 3つの どれかな？
> 　□ 1つ分の 大きさ　□ いくつ分　□ 何倍

- 3つとも常に表示する（到達済みかどうかで出し分けない）
- 選択を `self_label` に、`ai_judge` 判定との一致を `self_label_match` に保存
- **児童の選択が判定と食い違っても、訂正しない。** 「ちがうよ」「それは〜だよ」の類のメッセージを出すことを禁止する。記録のみ。

**ステップ3（目標の指定）**

`produced` に**含まれない**構造から1つ選ぶ（優先順：`tobun` → `hougan` → `bai`）。自己ラベルは目標決定に使わない。

| 指定 | 文言 |
|---|---|
| `tobun` | じゃあ 今度は「**1つ分の 大きさ**」を 求める 問題に して みよう。<br>{dividend}こを {divisor}人で 同じ数ずつ 分けたら、1人分は いくつに なるかな。 |
| `hougan` | じゃあ 今度は「**いくつ分**」を 求める 問題に して みよう。<br>{dividend}こを {divisor}こずつの まとまりに したら、まとまりは いくつ できるかな。 |
| `bai` | {divisor}を **1つの かたまり**と みると、{dividend}の 中に かたまりは いくつ あるかな。<br>それを「{divisor}の **何倍**」と いうよ。<br>{divisor}を もとにして、「**何倍**」を 求める 問題に して みよう。 |

`declared=指定構造`, `declared_by="system"`。目標の固定表示を更新。`bai` の2段構えは短縮しない。

### 3-6. 強（強度3、`response_type="prompt"`）

目標の指定＋**場面の固定**。`{ref_no}` は児童の成立問題のうち最新の表示番号。

| 指定 | 文言 |
|---|---|
| `tobun` | {ref_no}ばんの お話は **そのままで いいよ**。<br>おなじ ものを {divisor}人で 分けて、**1人分の 大きさ**を 求める 問題に かえられるかな？ |
| `hougan` | {ref_no}ばんの お話は **そのままで いいよ**。<br>おなじ ものを {divisor}こずつ まとめて、**まとまりの 数**を 求める 問題に かえられるかな？ |
| `bai` | {ref_no}ばんの お話は **そのままで いいよ**。<br>{divisor}こを もとに すると、{dividend}こは その **何倍**かな。それを 求める 問題に かえられるかな？ |

`declared=指定構造`, `declared_by="system"`。「お話は そのままで いいよ」は必ず文頭に置き、強調表示する（易しくする表現ではなく、題材を変えるのが作問だという思い込みを外すのが目的）。

### 3-7. 完了（`response_type="done"`）

`produced` が3つそろったとき：

> 3つ とも できたね！
> 1つ分の 大きさ、いくつ分、何倍——ぜんぶ ちがう ものを 求める 問題が そろったよ。

以降は予告支援を出さない。作問入力欄は開いたまま。

## 4. 式のカウンターバランス

`main.py` に設定テーブルとして置く（後から1箇所で変更できるように）。

```python
EXPRESSION_ASSIGNMENT = {
    "odd":  {1: "24÷6", 2: "24÷8", 3: "24÷3"},
    "even": {1: "24÷3", 2: "24÷8", 3: "24÷6"},
}
```

- `parity_group` は出席番号の奇偶（実装済みの列を使う）
- セッション開始時に決定し `sessions.expression` に保存。途中で変えない
- 管理画面から個別の式を上書きできる手段を残す（当日のトラブル対応用）
- 24÷4 を使わない理由：9/1 の紙の調査が全員 24÷4 で、練習効果が交絡するため

## 7. 受け入れ条件

### 状態機械（最重要）

- [ ] 不成立を3回連続 → `stuck_count` が 0 のまま
- [ ] 等分除→等分除→等分除 → `stuck_count` が 0→1→2 と動き、3問目で弱が出る
- [ ] 弱で「いくつ分をきく」と入力 → `declared_structure="hougan"`, `declared_by="child"`、目標が固定表示される
- [ ] その次に等分除 → `declaration_met=0`, `miss_count=1` → 中が出る
- [ ] 中の直後にまた予告と違う構造 → `miss_count=2` → 強が出る
- [ ] **包含除に到達 → `stuck_count` と `miss_count` が両方 0 に戻り、強度0の称賛が出る**（最も抜けやすい）
- [ ] 3構造そろう → done。以降支援なし
- [ ] `taiwa` / `resend` でカウンタが動かない
- [ ] Phase1 / Phase3 で予告支援が一切出ない
